WHY THIS FILE EXISTS
--------------------------------------------------------------------------------
A binary in a package is anonymous. This file is how anyone later can tell which
native library came from which source, which toolchain and which build machine.
Every time a binary is adopted into ../src/CodeBrix.Audio.FlacWriter/runtimes/
<rid>/native/, its section here is updated from that build's
output/<rid>/BUILD-INFO.txt.

Common to every entry below
--------------------------------------------------------------------------------
  Source          : flac/ (flac-1.5.0) - the unmodified Xiph release tarball
                    (upstream-downloads/flac-1.5.0.tar.xz; sha256
                    f2c1c76592a8...b920; see UPSTREAM.txt), plus
                    shim/codebrix_flac.c implementing the fixed contract
                    shim/codebrix_flac.h (API version 1)
  Compiled        : libFLAC only (src/libFLAC/*.c minus the Ogg files; on Windows
                    also src/share/win_utf8_io/win_utf8_io.c, which libFLAC's own
                    target lists - BSD-3), through flac's OWN CMake
                    (shim/CMakeLists.txt: add_subdirectory(flac EXCLUDE_FROM_ALL))
                    with BUILD_SHARED_LIBS / BUILD_CXXLIBS / BUILD_PROGRAMS /
                    BUILD_EXAMPLES / BUILD_TESTING / BUILD_DOCS / BUILD_UTILS /
                    INSTALL_* / WITH_OGG / ENABLE_MULTITHREADING all OFF. Static
                    libFLAC is linked into ONE shared library per RID. NOT built:
                    libFLAC++, the GPL flac + metaflac programs, src/share/
                    {grabbag,utf8,getopt,replaygain_*}, examples, tests, docs.
                    libFLAC's own defaults otherwise apply: WITH_ASM=ON (x86
                    SSE/AVX2 intrinsics with RUNTIME CPU detection; NEON on GCC/
                    clang arm64), 64-bit bit-writer words, _FORTIFY_SOURCE=2 and
                    -fstack-protector-strong where the compiler has them,
                    -fassociative-math family for libFLAC's float code (its own
                    flags). Each RID's libFLAC configuration is recorded below.
  Visibility      : -fvisibility=hidden for every object, libFLAC's included
                    (static libFLAC => FLAC__NO_DLL => FLAC_API is empty) +
                    --exclude-libs,ALL on Linux/Android; exports are EXACTLY the
                    23 functions of codebrix_flac.h - checked by every gate
                    (missing AND extra)
  Patches applied : NONE. patches/ is empty.
  Shipped names   : libcodebrix_flac.so / codebrix_flac.dll /
                    libcodebrix_flac.dylib - unversioned (SONAME/install name
                    unversioned too), because DllImport("codebrix_flac") probes
                    exactly those names
  Licence beside  : LICENSE-Flac.txt = licenses/LICENSE-Flac.txt = flac/
  every binary      COPYING.Xiph VERBATIM (BSD-3; md5 of the file
                    78a131b2ea50675d245d280ccc34f8b6), written and
                    checked by licenses/compose-license-flac.sh. No third-party
                    notice needs composing in: the compiled sources name only Josh
                    Coalson and the Xiph.Org Foundation; the two other notices in
                    them are public-domain dedications (md5.c, bitmath.h) with no
                    reproduction condition. --check re-runs that survey on every
                    bash build. flac-native-tools/.gitattributes marks the source
                    texts (flac/** and licenses/LICENSE-Flac.txt) -text.
  Smoke test      : ../smoke-test.c, built for the TARGET by the same CMake run
                    (codebrix_flac_smoke - it links its own static libFLAC, used
                    ONLY as an independent decoder) and run against the STAGED
                    (stripped) file, loaded by path: api_version == 1, libFLAC
                    1.5.0 version string; STREAM mode stereo 44.1 kHz 16-bit
                    level 5, 1 s of 440/660 Hz in 8 uneven chunk sizes, two
                    comments (one non-ASCII UTF-8): "fLaC", placeholder STREAMINFO
                    before finish, 3 patches all inside the header, patched total
                    44100 + non-zero MD5, read_header after finish == patched
                    header, libFLAC's decoder decodes the patched (MD5 checked)
                    AND unpatched stream sample-exactly and finds the comments +
                    the "reference libFLAC 1.5.0 20250211" vendor; PACKET mode
                    (verify=1, seek table every 4096, 512 B padding): only the
                    header reaches the output, 11 packets with first_sample ==
                    running sum summing to 44100, header patched at finish,
                    header + packets decode sample-exactly; the same options in
                    stream mode give byte-for-byte header + packets; 24-bit mono
                    48 kHz at levels 0 and 8 (verify=1) sample-exact; an empty
                    stream; and the contract's error paths (null handles, 12 bad
                    create arguments, every setter after start, seek table without
                    an estimate, illegal tag / non-UTF-8 value, write/finish
                    before start and after finish, an out-of-range sample rejected
                    with the encoder still usable, bad patch index, short buffers,
                    a non-subset block size refused with CBF_E_UNSUPPORTED +
                    "FLAC__STREAM_ENCODER_INIT_STATUS_NOT_STREAMABLE"). 118 checks.

                    ONE source fix was needed, in ../smoke-test.c - not in the
                    shipped library, which had already compiled and linked
                    cleanly when the smoke test failed to compile:
                      uint8_t small[8]  ->  uint8_t tiny[8]   (and its 5 uses)
                    <windows.h> pulls in rpcndr.h, which #defines `small` as
                    `char` (likewise near, far, hyper ...), so MSVC saw
                    "uint8_t char[8]" (error C2628). The variable was renamed,
                    and the smoke test now #defines WIN32_LEAN_AND_MEAN before
                    <windows.h>, which keeps rpcndr.h out altogether. Both
                    changes sit in the #if defined(_WIN32) block or are a local
                    rename, so the Linux / Android / macOS smoke tests are
                    unaffected (same 118 checks). Both RIDs were then rebuilt
                    from scratch; the records below are from those runs.
  Build warnings  : per RID, 6 x MSBuild MSB8029 ("Intermediate directory ...
                    under the Temporary directory") because -BuildRoot defaults
                    to %TEMP% - every build is a clean build, so it is moot.
                    Zero compiler (C....) or linker (LNK....) warnings in the
                    shim, the smoke test AND libFLAC.
